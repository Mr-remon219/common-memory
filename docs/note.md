# 设计备注：读取请求的模型路由

状态：Pi 原生读取与 settled-turn 异步提取切片已进入实现

## 当前实现切片

- 已实现共享 `RecallOrchestrator`、远程查询路由、最多三查询的稳定 RRF，以及基于 `expected_knowledge_revision` 的最终召回。
- 已实现 Pi 原生只读工具 `memory_recall`，直接调用共享 Recall Runtime，不经过 MCP。
- 模型失败会降级到本地算法；用户取消不会被转成降级成功。
- 已实现 raw `input` 暂存、`before_agent_start` 接受、用户 `message_end` 稳定 entry 绑定、`agent_end` 终态记录和 `agent_settled` 原子 observation/outbox 提交。
- 独立 extract worker 使用 SQLite lease/fencing、按 session+scope 串行、指数退避、content-addressed source digest 和有界 shutdown；hook/worker 失败均不影响主 Agent。
- `before_agent_start` 自动召回注入、完整 session ledger/compaction UI、其他 Agent 和 MCP 仍未实现。

## 当前决定

现阶段，Common Memory 的记忆读取只实现一种模式：

> 每次记忆请求都经过远程模型路由，由模型判断本次请求应主要使用确定性算法处理，还是需要模型进一步参与查询规划。

第一版不向用户提供“模型介入程度”选项，TUI 中暂不增加关闭、自适应或深度参与等配置。待读取链路稳定并取得真实的质量、延迟和成本数据后，再考虑提供可选模式。

## 建议流程

```text
Pi 发出记忆请求
  → 本地算法执行低成本的初步分析与检索
  → 远程模型检查任务和初步结果
  → 模型选择处理路线
      ├─ algorithm：现有算法结果已经足够
      ├─ hybrid：模型补充查询或过滤条件，算法重新检索
      └─ model_led：模型负责更完整的查询规划、候选判断与语义重排
  → 本地系统验证结果并按预算组装 Recall Pack
  → 返回给 Pi
```

模型路由不是象征性的空调用。模型至少需要判断：

- 当前请求是否真正需要长期记忆。
- 初步检索是否覆盖了请求中的主要意图。
- 用户表达是否含有算法难以处理的歧义或隐含指代。
- 是否需要生成多个查询、增加时间或类型过滤。
- 是否需要对候选进行更深的语义判断。

## 远程模型的地位

远程模型是读取链路中的语义路由器和可选规划器，不是权威存储，也不拥有治理权限。

即使模型选择 `model_led`，以下工作仍必须由本地确定性系统完成：

- 权限、披露范围和敏感内容检查。
- scope、状态、有效期和时间范围过滤。
- 正式事实、历史事实和候选记忆的边界判断。
- 冲突、替代关系和来源 ID 验证。
- token 或其他硬预算约束。
- 最终 Recall Pack 的结构校验。
- 任何正式记忆写入和治理操作。

模型不能直接编辑 YAML、访问仓库路径、绕过 Core 或把自己的推断声明为正式事实。

## 读取侧责任边界

读取模型不应直接放入 Core。建议在 Core 之外设置独立的 `RecallOrchestrator`：

```text
Pi Adapter
  → RecallOrchestrator
      → Core 本地查询与 FTS
      → Recall Planner Model
      → 本地 Recall Pack 编译器
```

Core 继续保持模型无关和确定性；`RecallOrchestrator` 负责协调本地检索与远程模型，但不获得写入 authority。

## 失败与降级

远程模型超时、拒绝、返回无效结构或暂时不可用时，读取请求必须自动降级到本地算法结果：

- 核心画像和安全边界仍然返回。
- 本地 scope、时间过滤和 FTS 检索仍然工作。
- 响应明确标记模型路由降级。
- 不能因为远程模型失败而编造记忆或放宽权限。

## 第一版压缩边界

第一版的主要压缩手段是选择更少、更相关的记忆，并为每条记忆选择合适的详情层级，而不是对所有候选进行有损改写。

第一版不做：

- 不引入 LLMLingua 一类 token 删除或 token pruning。
- 不压缩或改写安全边界、权限规则、用户明确修正和核心偏好。
- 不对代码、命令、路径、版本号、错误信息或配置片段进行无约束有损压缩。
- 不用模型摘要覆盖或替代正式事实与原始来源。
- 不在每次请求中重新总结全部候选记忆。
- 不把 Pi 的会话 compaction 摘要自动提升为 Common Memory 正式事实。
- 不把针对当前查询生成的一次性摘要保存为未来查询的唯一记忆表示。

允许的第一版压缩方式：

- 核心事实和安全边界原文硬保留。
- 普通正式事实以原子 statement 装载。
- 历史和证据按 Fact、Overview、Full Evidence 分层装载。
- 预算不足时按完整层级降级，而不是从文本中间截断。
- 复杂历史问题可以生成带来源 Fact ID 的一次性任务摘要，但该摘要只是派生响应，不具备治理权威。

## 未来可能的配置方向

读取链路稳定后，可以根据真实评测考虑在 TUI 中提供：

- 本地算法模式。
- 低置信时调用模型的自适应模式。
- 每次请求都经过模型审核的路由模式。
- 模型深度参与查询规划和上下文压缩的模式。

这些属于未来方向，不是当前版本范围。是否增加应以召回质量、误召回率、重复请求率、端到端延迟、远程调用成本和隐私影响的评测结果为依据。
